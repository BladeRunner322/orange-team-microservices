# ADR-014: Бэкапы и Disaster Recovery

## Контекст

Сейчас в проекте работает **локальный бэкап**: `scripts/backup-db.sh` дампит три базы (`auth_db`, `profiles_db`, `exercises_db`), сжимает gzip и кладёт в `/root/backups/YYYY-MM-DD_HH-MM-SS/`. Ротация — 7 дней. Cron на сервере, раз в сутки в 03:00 МСК.

**Проблема:** бэкапы лежат **на том же сервере**, что и прод. Это не защищает от:

- смерти диска / NVMe;
- случайного `rm -rf /root/backups`;
- компрометации сервера (атакующий удалит бэкапы первым делом);
- потери доступа к серверу.

Классический сценарий: cron годами пишет дампы локально, при первом инциденте выясняется, что восстанавливать нечего.

**Что нужно:** off-site копия бэкапов в независимом хранилище, с автоматической выгрузкой из уже существующего скрипта и простой процедурой восстановления.

## Решение

### Провайдер: Selectel Object Storage

VDS-сервер уже в Selectel (СПб, регион ru-1). Object Storage — S3-совместимое хранилище в том же регионе.

**Почему Selectel Object Storage:**

- **Трафик внутри Selectel не тарифицируется.** VDS → S3 в одном регионе бесплатен. Критично для ежедневной выгрузки.
- **Один биллинг.** Не надо держать аккаунт в другом сервисе.
- **S3-совместимость.** Работает через `rclone` / `aws-cli` / любой S3-клиент. Не привязываемся.
- **SLA и локация.** Данные в РФ, в том же дата-центре, что и сервер.

**Рассмотренные альтернативы:**

- **Backblaze B2** — дешевле, но зарубежный. RTT из РФ выше, оплата в валюте, риск блокировок.
- **Yandex Object Storage** — аналог, но VDS у нас в Selectel, трафик между провайдерами платный.
- **AWS S3 / GCS** — дороже, зарубежные.
- **MinIO на втором VPS** — ещё один сервер обслуживать, оверкилл для MVP.

### RPO и RTO

| Параметр | Значение | Что это значит |
|---|---|---|
| **RPO** (Recovery Point Objective) | 24 часа | При катастрофе теряем максимум сутки. Бэкап раз в сутки в 03:00 МСК. |
| **RTO** (Recovery Time Objective) | 2 часа | Время от «сервер умер» до «сервисы отвечают». |

**Триггеры пересмотра:**

- **RPO < 24 ч** — более частый cron (каждые 4–6 часов) или WAL-архивация Postgres.
- **RTO < 2 ч** — автоматизация развёртывания (Ansible / Terraform) + hot standby.

Оба — реальные пользователи / SLA / платящие клиенты. Для MVP текущих целей достаточно.

### Формат хранения

Скрипт `backup-db.sh` после локального дампа выгружает **тот же `.sql.gz`** в S3.

**Структура бакета:**

```
s3://orange-team-backups/
├── auth/
│   └── 2026-10-07_03-00-01/
│       └── auth_db.sql.gz
├── profiles/
│   └── 2026-10-07_03-00-01/
│       └── profiles_db.sql.gz
└── exercises/
    └── 2026-10-07_03-00-01/
        └── exercises_db.sql.gz
```

Префикс по сервису — чтобы при восстановлении не путать дампы. Имя папки с датой — как локально.

**Класс хранения:** «Холодное» (Cold) — бэкапы читаются только при восстановлении, значит холодный класс дешевле. Если Selectel не поддерживает Cold в текущем тарифе — Standard. Решается при настройке бакета.

### Retention

**Локально:** 7 дней (как сейчас).
**В S3:** 30 дней.

Разные retention, потому что S3 дешёвый и off-site должен хранить больше. Локально — быстрый доступ к свежим дампам, в S3 — история за месяц.

**Реализация:** удаление старых папок в S3 делает тот же cron-скрипт после выгрузки, командой `rclone delete --min-age 30d`.

### Инструмент: rclone

**Почему rclone, а не aws-cli:**

- Единый конфиг для любого S3-совместимого провайдера (Selectel / Yandex / B2 / MinIO).
- Простой `rclone.conf` вместо цепочки `~/.aws/credentials` + `~/.aws/config`.
- `rclone copy` и `rclone delete --min-age` покрывают всё, что нужно.
- Если меняем провайдера — правим одну строку в конфиге, не трогаем скрипт.

**Установка на сервер:**

```bash
curl https://rclone.org/install.sh | sudo bash
```

**Конфиг `~/.config/rclone/rclone.conf`:**

```ini
[selectel]
type = s3
provider = Other
endpoint = <SELECTEL_S3_ENDPOINT>
access_key_id = <SELECTEL_ACCESS_KEY>
secret_access_key = <SELECTEL_SECRET_KEY>
region = ru-1
acl = private
```

Ключи — сервисного пользователя Selectel (Object Storage → Пользователи → Создать).

**Хранение конфига:** шифруется через SOPS — `scripts/rclone.conf.enc`. CD расшифровывает и заливает на сервер вместе с `.env`. Единый подход с ADR-006: секреты в git зашифрованы, восстановление автоматическое.

### Изменения в backup-db.sh

После успешного локального дампа всех баз:

1. Для каждого сервиса — `rclone copy` дампа в `s3:orange-team-backups/<service>/<timestamp>/`.
2. После успешной выгрузки — `rclone delete --min-age 30d s3:orange-team-backups/<service>/`.
3. Ошибка выгрузки в S3 **не фейлит** локальный бэкап. В лог — `WARN`, exit code 0. Локальный успех важнее.

Скрипт остаётся идемпотентным: повторный запуск в ту же дату перезапишет файл.

### Процедура восстановления

Документируется в README (раздел «Бэкапы») после реализации. Коротко:

```bash
rclone lsf s3:orange-team-backups/auth/                    # список дампов
rclone copy s3:orange-team-backups/auth/<ts>/auth_db.sql.gz /tmp/restore/
gunzip -c /tmp/restore/auth_db.sql.gz > /tmp/restore/auth_db.sql
docker exec -it auth-postgres psql -U test -d postgres -c "CREATE DATABASE auth_restore;"
docker exec -i auth-postgres psql -U test -d auth_restore < /tmp/restore/auth_db.sql
docker exec -it auth-postgres psql -U test -d auth_restore -c "SELECT COUNT(*) FROM auth.users;"
```

Раз в месяц — прогонять восстановление последнего дампа в тестовую БД.

### Мониторинг бэкапов

Пока **без алертинга** — это отдельный ADR (Alerting и мониторинг). До его реализации минимум: раз в неделю вручную смотреть `/var/log/backup.log` и `rclone lsf s3:orange-team-backups/auth/ | tail -5`.

**Триггер на алертинг:** реальный пользователь / SLA / регулярный деплой → Alertmanager, алерт на «бэкап не появлялся > 36 ч».

## Последствия

**Плюсы:**

- Бэкапы выживают при смерти сервера, случайном удалении, компрометации.
- RPO = 24 ч, RTO = 2 ч — измеримые цели.
- Стоимость ~40–50 ₽/мес за 30 ГБ.
- Трафик VDS ↔ S3 внутри Selectel бесплатен.
- rclone конфиг в SOPS — единый подход с остальными секретами.
- Процедура restore документирована.

**Минусы:**

- Ещё один внешний сервис в зависимостях.
- Ещё один секрет (`rclone.conf`) для ротации.
- Off-site может молча не работать — нужен алертинг.
- Retention в S3 (30 дней) ≠ локально (7 дней) — помнить при отладке.
- RPO 24 ч не подходит для критичных данных.

**Когда пересмотреть:**

- RPO < 24 ч → WAL-архивация + инкрементальные бэкапы.
- RTO < 2 ч → автоматизация развёртывания + hot standby.
- Цена S3 выросла → холодный класс, lifecycle-policy, архивы.
- Selectel меняет условия → переезд на другого S3-провайдера (одна строка в rclone.conf).
- Вторая площадка → репликация бэкапов между двумя S3.

## Плейсхолдеры для реализации

Перед реализацией заполнить:

- `<SELECTEL_S3_ENDPOINT>` — эндпоинт бакета (пример: `https://s3.ru-1.storage.selcloud.ru`). Панель Selectel → Object Storage → бакет → Свойства.
- `<SELECTEL_ACCESS_KEY>` / `<SELECTEL_SECRET_KEY>` — S3-ключи сервисного пользователя.
- Имя бакета: `orange-team-backups` (по умолчанию).
