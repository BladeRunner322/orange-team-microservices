# ADR-005: Распределение портов

## Контекст

Проект — монорепозиторий с несколькими сервисами, каждый со своими портами. У сервисов есть несколько типов портов: gRPC, HTTP (health/metrics), Postgres, Redis.

Без явной стратегии распределения портов возникают проблемы:

- **Конфликты на хосте.** Два сервиса не могут пробросить один хост-порт.
- **Сложность расширения.** При добавлении нового сервиса — какой порт занять?
- **Путаница.** Порт 8083 — это чей? Какой сервис? HTTP или что-то другое?
- **Смешение Docker и локальной разработки.** Локально поднятые сервисы конфликтуют с контейнерами на тех же портах.

Нужна единая стратегия, которая делает распределение предсказуемым и читаемым.

## Решение

**Range-based allocation с последовательным заполнением внутри диапазона.**

Каждому **типу порта** выделяется свой диапазон. Внутри диапазона порты идут последовательно (следующий свободный). Для локальной разработки применяется **смещение +10**.

### Диапазоны портов

| Диапазон | Назначение | Примеры |
|---|---|---|
| **50051–50060** | gRPC-сервисы | Auth=50051, Profiles=50052, Exercises=50053, ... |
| **8080–8089** | HTTP-сервисы (Docker) | Auth=8080, Gateway=8081, Profiles=8082, ... |
| **8090–8099** | HTTP-сервисы (локально, +10 от Docker) | Auth=8090, Gateway=8091, Profiles=8092, ... |
| **5432–5439** | PostgreSQL (хост-порт) | Auth=5432, Profiles=5433, Exercises=5434, ... |
| **6379–6389** | Redis (хост-порт) | Auth=6379, Gateway=6380 |
| **9090** | Prometheus | Фиксирован |
| **3000** | Grafana | Фиксирован |
| **3100** | Loki | Фиксирован |

### Правила

1. **HOST_PORT уникален.** CONTAINER_PORT может повторяться у разных контейнеров (разные namespace в docker-сети).

2. **Внутри диапазона — последовательно.** Новый сервис получает следующий свободный порт в своём диапазоне. Не пытайся «втиснуть» порт в середину.

3. **Локальная разработка — Docker-порт + 10.** Для gRPC это 50061, 50062. Для HTTP — 8090, 8091, 8092. Смещение позволяет запускать сервисы локально (`go run`), не конфликтуя с уже поднятыми Docker-контейнерами.

4. **Postgres и Redis локально не поднимаем.** Используем Docker-инстансы. Смещение не нужно.

5. **Каждый порт — в `.env`.** Никогда не хардкод в коде или в compose. Все через переменные:
   - **Хост-порты** — в корневом `.env` (`AUTH_GRPC_PORT`, `AUTH_POSTGRES_PORT`, `AUTH_REDIS_PORT`, `PROFILES_GRPC_PORT`, `PROFILES_POSTGRES_PORT`, ...).
   - **Внутренние** — в сервисных `.env` (`GRPC_PORT`, `HTTP_PORT`, `POSTGRES_PORT`, ...). Значения `POSTGRES_PORT` и `REDIS_*` в сервисных `.env` — это порты **внутри контейнера**, не на хосте.

> ⚠️ Имена переменных в корневом и сервисных `.env` различаются. Корневой — про хост-порты (`AUTH_POSTGRES_PORT`), сервисные — про внутренние (`POSTGRES_PORT`). `docker-compose.yml` пробрасывает `${AUTH_POSTGRES_PORT}:5432`, а сам сервис внутри контейнера ходит на `postgres-auth:5432`.

6. **Не полагаться на дефолты.** Всегда задавать значения явно — даже если они совпадают с дефолтом в коде.

### Текущее распределение

| Сервис | gRPC | HTTP | Postgres (хост) | Redis |
|---|---|---|---|---|
| **Auth** | 50051 / 50061 | 8080 / 8090 | 5432 | 6379 |
| **Gateway** | — | 8081 / 8091 | — | 6380 |
| **Profiles** | 50052 / 50062 | 8082 / 8092 | 5433 | — |
| **Exercises** | 50053 / 50063 | 8083 / 8093 | 5434 | — |

(Формат: `Docker / Локально`. Прочерк — сервис не имеет такого порта.)

## Последствия

**Плюсы:**

- **Читаемо.** По номеру порта видно тип сервиса. 50052 — gRPC. 8083 — HTTP. 5435 — Postgres.
- **Предсказуемо.** Новый сервис — следующий свободный порт. Не надо думать.
- **Без конфликтов.** Диапазоны не пересекаются. Смещение +10 разводит Docker и локальную разработку.
- **Легко документировать.** Эта таблица — единый источник истины.
- **Совместимо с Docker Compose и k8s.** В compose — явные `ports:`. В k8s — ClusterIP-сервисы внутри сети используют CONTAINER_PORT.

**Минусы:**

- **Пропуски при удалении сервиса.** Если убрать Profiles — порт 50052 освободится, но повторно использовать его для нового сервиса нельзя (иначе путаница с прошлым). Соглашение: **освободившиеся номера не переиспользуются**.
- **Диапазоны конечны.** 50051–50060 = 10 gRPC-сервисов. Если станет больше — расширять диапазон (например, 50051–50100).

**Когда пересмотреть:**

- Если сервисов станет больше 10 в одном диапазоне — расширить границы.
- Если перейти на k8s — для inter-service коммуникации достаточно CONTAINER_PORT + Service DNS. HOST_PORT нужен только для внешнего мира.
- Если сервисы перестанут быть в одной docker-сети — потребуется отдельная стратегия для cross-network адресов.

## Замечания

- **Порт не является идентификатором сервиса.** Сервис идентифицируется **именем** (`auth-service`, `profiles-service`). Порт — деталь подключения.
- **Изменение порта — не ломающее изменение.** Если 50052 занят другим сервисом на хосте (что маловероятно), можно сдвинуть без правок кода — только `.env`.
- **Документация — обязательна.** При добавлении сервиса обновлять эту таблицу.
