# ADR-001: Профиль пользователя

## Контекст

В монолите данные пользователя жили в одной таблице `app.users`:

- credentials (email, password_hash) — кто ты
- профиль (sex, weight_grams, birth_date, height_cm) — данные о тебе
- role — что тебе можно
- user_workout_score — накопленный счёт

При распиле на микросервисы:

- **Auth** владеет credentials и role
- **Users** должен владеть профилем
- Встал вопрос: **когда** создаётся запись в Users и что делать с пустым профилем

В монолите профиль был необязательным — можно было зарегистрироваться и никогда не заполнить вес/рост. `personal_score_coefficient` в `CreateWorkout` возвращал `1`, если `weight_grams` или `height_cm` NULL:

\`\`\`go
if user.WeightGrams == nil || user.HeightCM == nil {
    return 1
}
\`\`\`

То есть пустой профиль не блокировал создание тренировок.

## Решение

- **Владелец профиля:** Users-сервис.
- **Когда создаётся:** лениво, при первом обращении `GET /users/me`. Auth не уведомляет Users при регистрации.
- **Обязательные поля:** нет. `sex`, `weight_grams`, `birth_date`, `height_cm` — все nullable.
- **Пустой профиль:** допустим. Workouts получает профиль через синхронный gRPC-вызов `Users.GetProfile(user_id)` при создании тренировки. Если `weight` или `height` отсутствуют — `personal_score_coefficient = 1`.
- **Никаких событий и sync-вызовов Auth → Users** при регистрации.

## Последствия

**Плюсы:**

- Нет инфраструктурного оверхеда (нет брокера, нет outbox, нет distributed-транзакций).
- Auth не зависит от Users.
- Users не зависит от Auth.
- Поведение совпадает с монолитом: пустой профиль — норма.

**Минусы:**

- Если пользователь сразу создаёт тренировку, Workouts делает синхронный вызов в Users. Если Users недоступен — `CreateWorkout` упадёт.
- Профиль создаётся только при первом `GET /users/me`. Если клиент никогда не открывает профиль — записи в Users нет. Это ок для MVP, так как работать с ней всё равно никто не будет.

**Когда пересмотреть:**

- Если появится требование «профиль создаётся в момент регистрации» — переход на событие `user.registered` (Redis Streams / NATS).
- Если `GetProfile` станет горячим — кэш в Gateway или в Workouts.
