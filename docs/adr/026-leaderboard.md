# ADR-026: Сервис рейтинга (Leaderboard)

## Контекст

Gateway уже объявляет маршруты дневного, недельного и месячного рейтингов. Workouts хранит начисленные очки каждой тренировки и время её завершения. Текущий `GetUserScore` возвращает суммарные очки текущего пользователя за всё время.

## Решение

### Правила рейтинга

- День начинается в полночь UTC, неделя — в понедельник в полночь UTC, месяц — первого числа в полночь UTC. Интервал включает начало периода и исключает конец.
- Участвовать может любой пользователь. В расчёт входят завершённые, неудалённые тренировки, чей `completed_at` попадает в период. По каждому пользователю суммируется сохранённый `workout_score`. Строки с нулевой суммой отфильтровываются.
- Порядок определяется по сумме очков по убыванию и `user_id` по возрастанию. Leaderboard присваивает последовательные места с единицы. Workouts ограничивает число строк после сортировки.
- При изменении сложности в каталоге уже добавленные упражнения сохраняют свою сложность по [ADR-025](025-workouts.md).

### Контракты и зависимости

- Внутренний gRPC-метод Workouts принимает начало и конец периода и положительный лимит. Он возвращает упорядоченный список пар `user_id` и суммы очков. Workouts проверяет границы, лимит и доступ сервисного клиента.
- Leaderboard определяет границы периодов и использует один порт для получения рейтинга из Workouts. Для MVP gRPC-клиент реализует этот порт.
- Gateway вызывает `GetDaily`, `GetWeekly` и `GetMonthly` на маршрутах `GET /leaderboard/daily`, `GET /leaderboard/weekly` и `GET /leaderboard/monthly`. Ответ содержит границы периода, время обновления и строки с местом, идентификатором пользователя и очками.

### Обновление и чтение

- Leaderboard загружает три топа при запуске, затем обновляет их по таймеру. Интервал настраивается, начальное значение — одна минута. Каждый вызов Workouts имеет таймаут, а цикл останавливается при завершении сервиса.
- Каждый успешный ответ заменяет снимок соответствующего периода в памяти вместе со временем обновления. Пустой рассчитанный топ — успешный результат.
- HTTP-запросы читают готовый снимок. При сбое Workouts Leaderboard отдаёт последний успешный снимок за текущий период и его время обновления. Если снимка за текущий период ещё нет, Gateway возвращает `503`. Это правило действует и после перехода через границу периода.

## Последствия

- Пользовательские запросы переиспользуют готовые топы. Стоимость SQL-агрегации зависит от расписания обновления.
- Новые очки становятся видны после успешного обновления. При сбое время обновления позволяет клиенту оценить, насколько актуален рейтинг.
- Готовые топы хранятся в памяти экземпляра и загружаются заново при запуске. Источник очков — PostgreSQL сервиса Workouts.
- Kafka и Notification запланированы отдельным этапом по [ADR-024](024-kafka-notification.md). Событийная проекция Leaderboard рассматривается отдельным ADR.
