# Context — файлы передачи контекста между чатами

Каталог для handoff-документов: когда работа над проектом идёт сессиями и в какой-то момент нужен новый чат с ИИ, эти файлы передаются вместо пересказа всей истории.

## Что лежит

- **`Context.md`** — единый документ состояния: общее состояние проекта (сервисы, ADR, инфраструктура, roadmap, принципы) + детали текущего сервиса (что готово по шагам, принятые решения, что осталось, ключевые сигнатуры). Всё в одном файле, чтобы передавать в новый чат одним куском.
- **`Rules.md`** — правила работы: формат ответа на правки, блоки «Было/Стало», соглашения по веткам, коммитам, PR, git tags (semver), формат ответа на «я не понимаю».

## Когда обновлять

- **При передаче в новый чат.** Пересказать актуальное состояние в `Context.md` и убедиться, что `Rules.md` актуален.
- **При закрытии значимой вехи.** Новый сервис в проде, закрытие уровня эволюции ADR-019, крупный рефакторинг — обновить соответствующий раздел, чтобы следующий чат начался с верной картины.
- **Не при каждом коммите.** Файлы описывают состояние, а не историю. История — в `git log` и ADR.

## Как использовать

1. Начать новый чат.
2. Скинуть `Rules.md` и `Context.md` — в этом порядке.
3. Дополнительно — актуальные файлы, которых нет в контексте (например, `.proto`, текущий `server.go`, если он в работе).
4. Дать первое конкретное указание («продолжаем шаг 5 Workouts»).

## Чего НЕ делать

- Не редактировать вручную без причины — если правишь, коммить отдельным PR `docs(context): ...`.
- Не добавлять сюда ADR (они в `docs/adr/`), backlog (`docs/backlog.md`), readme проекта.
- Не складывать сюда скриншоты, бинарники, временные файлы.
